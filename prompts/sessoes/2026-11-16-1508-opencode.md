**O achado mais grave estava classificado errado (agora é o P0 #1)**

- O `apps/api/src/auth/jwt.config.ts:5` lê `JWT_SECRET` no momento do import, antes de o
  `ConfigModule.forRoot()` carregar o `.env`. Por isso, colocar o segredo no `apps/api/.env`
  **não tem efeito**: a API continua assinando com `'dev-only-insecure-secret'`, e quem conhece
  esse fallback consegue forjar tokens de qualquer usuário. Além disso, o `.env.example` nem lista
  a variável.

**Verificações que faltavam e foram adicionadas**

- **Não existe CI de teste, lint ou build.** O único workflow é o de review, então as "regras de
  CI" do fechamento não teriam onde rodar.
- **Erros 500 vazam dados no log:** o `apps/api/src/common/problem-details.filter.ts:46` loga a
  exceção inteira, e um erro de query do Drizzle inclui os parâmetros (`password_hash`, e-mail).
- **Senha do login sem limite de tamanho:** o `signInSchema` não tem `max`, então cada request pode
  forçar o `scrypt` sobre até ~100 KB.
- **Enumeração de usuários:** `POST /users` responde `409 Email already registered`.
- **`page` sem máximo** gera `OFFSET` enorme num endpoint público.
- **Swagger e `X-Powered-By`** ficam expostos em produção.
- **No web**, o `postId` vai para a URL da API sem `encodeURIComponent`: `/posts/..` acaba
  chamando `GET /` da API.
- **No workflow de review**, as actions não estão fixadas por SHA, e o diff do PR é entrada não
  confiável para o agente (prompt injection).
- **No preflight:** varrer o histórico do git com `gitleaks` (hoje só se olha o working tree);
  rodar `pnpm audit` e revisar licenças; conferir se o secret `CLAUDE_CODE_OAUTH_TOKEN` existe.
- **Nos testes e2e**, faltam casos para: `GET /posts/:id/comments/:commentId`, `parentId` de
  outro post, `Content-Type` inesperado e `page` além do total.

**Achados corrigidos ou rebaixados**

- **`thumbnailUrl`:** `javascript:` dentro de `<img src>` não executa e nenhum código do servidor
  busca a URL, então não há XSS nem SSRF hoje. O risco real é rastreamento por URL externa.
  Continua P0 por ser contrato, mas a severidade caiu.
- **Limite de body:** o Express já aplica 100 KB por padrão. Também tirei a recomendação de
  `enableCors`: sem CORS, a API só aceita a mesma origem, que é o mais seguro.
- **Índice em `post_likes(post_id)`:** a chave primária `(post_id, user_id)` já cobre essa busca.
- **Corrida em `upsertTags`:** com `ON CONFLICT DO NOTHING` em `READ COMMITTED` ela não deve
  acontecer. Marquei como provável falso positivo, a ser provado com teste.
- **`GET` de comentário:** `ApiBearerAuth` e `Location` não se aplicam a um `GET` público, e
  `postIdSchema` é o mesmo `z.uuid()`. Virou um problema só de nome.
- **`.env`:** confirmei que só os `.env.example` estão versionados.
